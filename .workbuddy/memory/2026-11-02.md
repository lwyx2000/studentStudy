## 部署故障修复：前端 Docker 构建失败
- 现象：Jenkins 部署在 `前端 builder 6/6 RUN npm run build` 失败，报 `Cannot find native binding` / `Cannot find module '@rolldown/binding-linux-x64-musl'`（npm bug #4828）。
- 根因：`package.json` 中 `vite` 为 `^8`（实际 8.0.16，基于 rolldown 打包）。构建镜像 `node:22-alpine` 自带 npm 10.9.9 存在可选依赖解析 bug，不会自动安装 rolldown 的 musl 原生 binding，导致 vite build 缺原生模块。
- 修复：改 `careless-correction/Dockerfile` —— 构建阶段 `npm install -g npm@latest` + `npm install --include=optional`，并兜底按已装 rolldown 版本显式补装 `@rolldown/binding-linux-x64-musl`；`.dockerignore` 排除本地 Windows `package-lock.json`。
- 已提交推送：`2614aff`（main）。重新触发 Jenkins 部署即可。
- 备注：上一轮的打卡逻辑/动画/统计页改动经核查已提交在 main（git diff HEAD 无差异），本次部署会一并包含。

## 全部审计问题已修复（commit ffd83f9，已推送 main）
- **安全**：JWT 密钥不再有默认值——`Settings` 检测到空/示例值时自动生成随机密钥并写入数据卷 `data/.jwt_secret`（`@lru_cache` 保证进程内一致）；docker-compose 去掉 `${JWT_SECRET:-dev-...}` 兜底；Jenkinsfile 部署时检测到空值/示例值自动生成 48 位随机串写服务器 .env。删掉 `/auth/child-login`。注册加密码强度（≥8 位且字母+数字）+ 已有家长后需 `REGISTER_INVITE_CODE`。CORS 改白名单（默认 localhost/127.0.0.1/capacitor://localhost）+ `allow_credentials=False`。`/docs` 默认关闭（`ENABLE_API_DOCS`），nginx 层 `location ~ ^/(docs|redoc|openapi\.json) { return 404; }`。后端 `.dockerignore` 排除 .env/data/uploads/tests，并 `git rm --cached careless-correction-api/.env`。
- **数据一致性**：`children._purge_owned_rows` 按外键顺序清 17 张子表再删用户；`delete_task_permanent` 先删 SubTask；任务/子任务/习惯写接口全部 `require_parent`；打卡积分服务端重算（子任务按 title 匹配数据库，必做=子任务分或主任务分，可选=2/项，全完成由服务端判定，快照 points 被数据库值覆盖）；`uq_pending_sunlight_checkin` 唯一索引 + 存量去重迁移 + 审批/驳回条件 UPDATE + `on_conflict_do_nothing`；阳光/苹果扣减改 `WHERE 余额>=cost` 条件 UPDATE；徽章解锁 `on_conflict_do_nothing` 且奖励 SQL 自增；`zero_loss_days` 改日期差集；SQLite 开 WAL + busy_timeout=5000；迁移不再 DROP 表。
- **上传/LLM**：上传按文件头校验图片类型 + `MAX_UPLOAD_MB`（默认 8）+ 服务端随机文件名；`services/llm.validate_endpoint` 解析 DNS 拒绝内网/回环/保留地址（`LLM_ALLOW_PRIVATE_ENDPOINT=true` 可放开），`follow_redirects=False`。

## 第三轮审计修复（打卡计分 / LLM / 性能）
- **P0 打卡刷分**：`completed_tasks` 快照里同一项重复 N 次会被重复计分（实测 1 项 10 分 × 5 份 → 记 50 分）。修复：`_sanitize_completed_tasks_snapshot` 按 `subTaskId`（无则 title）去重，`_submit_checkin` 再用 `counted` 集合二次兜底，重复项记 0 分且 `verified=False`。
- **P0 同名小任务算错**：旧实现只按 title 建索引，两个主任务下同名但分值不同的小任务会全部按第一条算。改为 `subtask_by_id` 精确匹配 + `subtask_by_title` 兜底；前端打卡页快照增加 `subTaskId: item.id`。
- **P0 LLM Key 被覆盖**：`GET /llm/config` 回 `apiKey='***'`，前端保存时原样回传 → 真实 Key 被写成 `***`。后端 `_clean_api_key` 忽略占位符；前端不再回传 `***`、测试连接改走后端 `/llm/test`（浏览器直连大模型会被 CORS 拦）。
- **P1 周六算工作日**：`_matches_week_day` 用 `0 < weekday()+1 < 7`，周六(5+1=6) 被当工作日，与前端 `today>=1&&<=5` 不一致 → 周六「全部完成奖励」永远拿不到。改 `weekday() < 5`。
- **P1 习惯图片被清空**：前端 `updateHabit`/`syncStepsToBackend` 只回传 `instruction/order`，后端是「先删后插」全量替换 → 步骤图片丢失；`restoreHabit` 展开整个 habit 也会触发。改为 `stepsPayload()` 带上 imageUrl/gifUrl，restore 只发 `{id, active}`。
- **P1 永久删习惯 500**：`Task.fk_habit_sops` 引用且非级联，开 `foreign_keys=ON` 后必崩。删前把 Task / TaskWeeklyProgress 的 fk 置 NULL。
- **P1 打卡参数走 URL 过长**：中文标题 percent-encode 后膨胀 3 倍，清单多几项撞 nginx 8KB 请求行（414）。新增 `POST /checkins/submit` 收 JSON body（`_submit_checkin` 为共用实现），保留 query 版兼容已装 APK。
- **P2 性能**：`main.py` 新增 `_create_indexes()`（20 个索引，单条失败只告警不阻断启动）+ `_normalize_checkin_dates()` 把历史 `2026/8/1` 归一成 ISO；`_has_checked_today` 改等值查询走索引；`_streak_snapshot` 一并返回 `checked_today` 少查一次库。
