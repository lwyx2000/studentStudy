# 2026-11-01

## 打卡审批阳光逻辑修复 + 连击动画 + 打卡统计页

### 后端（careless-correction-api）
- `app/routers/checkins.py`
  - 重写连续天数计算：`_approved_dates` / `_calc_streak(dates, anchor)` / `_calc_best_streak` / `_streak_snapshot` / `_refresh_streak_days`。
    旧实现以「本次审批的打卡日期」为起点覆盖写入，**补打卡历史日期会把已有连击改成 1**；现在以今天（今天未通过则昨天）为锚点动态重算，并保留最佳连击。
  - 打卡提交新增未来日期校验（400）。
  - 同日重复记录治理：提交时先取同日全部记录，有 approved 直接拒绝，多余 pending/rejected（且无待收集阳光）会被删除，避免家长审批两条、重复发阳光。
  - 审批通过时待收集阳光改为「该打卡已存在任何 PendingSunlight（含已收集）就不再生成」，未收集的会按最新分值同步金额。
  - 新增 `GET /checkins/stats?child_id&days`：连续/最佳/累计天数、本月（含待审批）、每日打卡阳光、每日 collected 状态、近 6 个月汇总、daily 日历数组。
  - 提交接口返回 `streak: {days, approvedDays, bestDays, checkedToday, isNewToday, todayDate}`，供前端连击动画使用。
- `app/routers/points.py`
  - 扣阳光余额不足时报 400（原来 `max(0, ...)` 静默截断，流水与实际账不符）。
  - 收集阳光改为条件 UPDATE 抢占（`WHERE collected=0`）+ SQL 原子自增，防并发/双击重复入账。
- 新增 `tests/test_checkin_streak.py`（5 个用例），`tests/` 共 12 个用例全过。运行需 `D:/Python310/python.exe -m pytest`（系统默认 python 3.13 无依赖）。
